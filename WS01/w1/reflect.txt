In workshop 1, we learned:
1. How to receive program arguments from the command line using syntax: int main(int argc, char* argv[])
2. How to access a variable defined in a different translation unit using "extern" keyword. 
   The "extern" keyword identifies external linkage. We declared two variable using syntax "extern double g_taxrate; extern double g_dailydiscount;" in FoodOrder.h, and defined them in FoodOrder.cpp file. This makes "g_taxrate" and "g_dailydiscount" accessible by another translation unit. As a result, in w1p1.cpp and w1p2.cpp, the main function can directly access the same entities g_taxrate and g_dailydiscount declared in FoodOrder module and assign values to them. 
3. How to declare a local variable that resides in memory throughout the lifetime of the program using static variable.
   Static keyword identifies internal linkage. We declared a counter in FoodOrder module using syntax: static int counter{};. The counter is not invisible to other modules like w1p1.cpp and w1p2.cpp but is visible within FoodOrder module. "static" makes "counter" variable resides in memory throughout the lifetime of the program. When FoodOrder::display(std::ostream& ostr) const function was called in w1p1.cpp and w1p2.cpp, the counter will add 1. Although the counter was declared in display function, the same variable will last and will not be defined again, adding 1 on to the value every time the function was called. This makes static variables "counter" useful in my solution because it uses a single memory allocation to accumulate the orders every time the display function was called that improves memory efficiency. We achieved this effect without declaring a global variable that helped in organizing the code.
   The biggest different between internal linkage and external linkage is that the variable identified as internal linkage is not accessible by a different translation unit from which it was declared. However, external linkage variable can be accessible by different translation unit.
