****design and code a templated class that allocates and deallocates dynamic memory
In the Collection template class, we allocates and deallocates dynamic memory: 
	class Collection {
		std::string m_name{};
		T* m_items{};
		unsigned m_size{};
		void (*observer)(const Collection<T>&, const T&);
		void resize(size_t newSize) {
			T* tmpItems = new T[newSize];
			for (size_t i = 0; i < m_size; ++i) {
				tmpItems[i] = m_items[i];
			}
			delete[] m_items;
			m_items = tmpItems;
		}
------------------------------------------------------------------------------------------------
	~Collection() {
		delete[] m_items;
	}

A functor (function object) and a lambda expression are both allowed you to create callable objects.

We implemented a lambda function in workshop 5 w5 module, using syntax:

And a functor in Collection template class as below:
void setObserver(void (*observer)(const Collection<T>&, const T&)) {
	this->observer = observer;
}

Lambda expression is a inline function has direct access to non-local variables with its referencing environment, unlike a function pointer. When you want to capture local variables without explicitly passing them as arguments, you can use one. The utilizations of lambda expression is when you need a short, inline and reusable operation that used locally and in a particular context. We used fixPrice() in w5 to adjust the price of the books based on requested logic.

A functor is used when we want to reuse the operation in different parts of our codes. And when we want to hold state across multiple calls. In w5, two different functions that take the same types of parameters are designed, we passed these function to setObserver() function using functor: void (*observer)(const Collection<T>&, const T&) and saved it to a Movie and Books objects' member variables respectively. ****the classes Movie and Book contain almost identical logic in loading data from the file. How would you redesign the classes in order not to duplicate that logic?

The best way is to create a base class which Book and Movie derived from. This class has a member function to load the data from file, and extract each line from the file based on different derived class. We will need to create a pure virtual function to that is to extract each token in each line based on different type of the object. In the load function of base class, we call this 
pure virtual function.
In classes Movie and Book, we will need to create a member function using the same name as the pure virtual function. Then we move the logic in one-argument constructor that extract the tokens from data to the newly created member function. So when we use base class function to load the file, it will automatically call the token-extracting function based on the object type.
