a class that allows only one instance to be created is called a singleton. Can you think at another way to create a singleton without using static members? How would that object be managed?
ANS: Using external management entirely and managing the singleton's lifecycle outside the class, ensuring only one instance is created and shared can create a singleton without using static members. This can be achieved by utilizing an external context or configuration class that holds and provides access to the singleton instance.
1. We still use private constructor to prevent instantiation.
2. Delete copy constructor and assignment operator to avoid instantiation.
3. Add a friend class Manager allows only Manager can create instances.
4. a Manager class use a share_ptr to hold the instance's address. and create methods to manages the lifecycle and access to singleton instances such as getInstance or resetInstance.
This approach can ensure singleton pattern is implemented without using static members.

the class Database has a resource attribute (the database instance), yet no copy/move operations were implemented. Is that a bug (justify your answer)?
ANS: The resource attribute -- database instance -- has type: static std::shared_ptr<Database>, which is a smart pointer that 
1. copies itself in a copy construction
2. transfers ownership of the object or resource in move construction and move assignment
3. releases itself from its object or resource and reattaches itself in a copy assign
4. calls its object's or resource's destructor only if it itself is being destroyed and no other smart pointer shares ownership of the object or resource
It means we don't have to manually implement copy/move operations to use this resource.
